原 `conversation-grounding-features.md` 中的 GRD-001 至 GRD-020 已全部交付；实现入口和自动化
测试也已逐项复核。本文件只记录不属于现有完成定义、尚未排期的扩展能力，不能用来放宽稳定
协议中的 fail-closed、工具授权、证据持久化或发布门禁。

## 当前结论

- GRD-001 至 GRD-020 均已完成，没有需要从原清单继续执行的遗留项。
- OpenAI Responses 原生 web search 已进入统一证据账本；其他 Provider 在没有专用归一化适配时
  仍只能产生 `unverified` 内容。
- 加密 payload 引用和保守语义复核都已有领域契约，但生产环境没有默认后端；两者是可选增强，
  不是授予 `verified` 的前置条件。

## FUT-GRD-001 扩展 Provider 原生工具证据归一化

状态：设计完成，等待实施。

[详细设计与实施计划](provider-native-tool-evidence-normalization.md)

当前边界：只有 OpenAI Responses 的原生 web search 会转换为 `ProviderNativeToolResult`、统一调用
事件和 observation 证据。Anthropic、Moonshot 及其他 Provider 即使能够执行原生搜索，在缺少
专用 adapter 时也不会获得证据资格。

计划范围：

- 按 Provider 单独解析原生调用生命周期、来源引用、subject、观测时间和失败状态。
- 复用现有脱敏、digest、Schema、作用域和持久化门禁，不为 Provider 增加旁路。
- 对缺引用、截断、失败或未知响应格式保持 `unverified`，不得从搜索正文推断证据。
- 为每个 adapter 增加成功、失败、敏感信息脱敏、混合 MCP 证据和协议漂移测试。

完成标准：该 Provider 的原生工具结果能够进入统一事实账本，并通过与 OpenAI/MCP 相同的声明级
验证；关闭或移除 adapter 后仍安全降级。

## FUT-GRD-002 加密原始证据快照后端

状态：可选未来规划，未排期。

当前边界：`ToolEvidenceRecord` 和数据库已支持带过期时间的 `encrypted://` payload 引用，并
拒绝明文引用；应用尚未提供密钥管理、加密对象存储、授权读取和到期清理实现。当前稳定路径只
保存规范化事实、脱敏摘要和 digest。

计划范围：

- 定义密钥轮换、最小权限读取、删除级联和保留期清理协议。
- 将 payload 存储与事实账本事务通过幂等引用衔接，失败时不得影响 fail-closed 行为。
- 确保日志、指标、导出和普通 UI 永不包含原始私有结果或凭据。
- 增加密钥不可用、对象缺失、过期、篡改和会话删除测试。

完成标准：只有获授权的复验流程能够在保留期内读取并校验快照；快照不可用时，系统仍以规范化
事实和 digest 为唯一稳定依据，不自动升级可信等级。

## FUT-GRD-003 生产级保守语义复核器

状态：可选未来规划，未排期。

当前边界：`ClaimEvidenceReviewer` 接口及“只能拒绝、不能升级”的组合规则已有领域测试，但生产
依赖注入没有配置默认复核器。当前 `verified` 完全由确定性的 kind、capability、subject、scope、
时效、完整性和持久化检查决定。

计划范围：

- 仅在确定性门禁通过后执行复核，并把超时、错误或不确定结果解释为拒绝或降级。
- 对复核输入做最小化和脱敏，不发送无关工具原文、凭据或用户私密正文。
- 固定模型与协议版本，记录安全枚举指标，不记录自由文本解释。
- 增加提示注入、模型不可用、结果漂移和成本/延迟预算测试。

完成标准：启用复核器不会使任何原本被确定性门禁拒绝的绑定通过；关闭复核器不会改变现有稳定
协议和三个发布不变量。

## 规划项准入规则

- 新工作应分配新的实现编号，不重新打开 GRD-001 至 GRD-020。
- 每项能力都必须同时更新稳定协议、实现入口、迁移策略和自动化验收测试。
- 未完整交付时只能保持现有 `unverified`/`failed` 降级，不能添加临时可信旁路。
- 发布门禁继续固定检查：unsupported claim 通过数为零、verified 证据持久化率为 100%、重复
  副作用数为零。
